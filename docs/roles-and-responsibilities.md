# Roles & Responsibilities (RACI)

**R = Responsible for doing the work; A = Accountable for the outcome; C = Consulted; I = Informed.** This is a proposed role model; a real organization must designate actual people and avoid conflicts of interest where feasible.

| Activity | Executive sponsor | GRC Lead | IT Admin | People Ops | Manager | System/Data owner | Incident Response Lead | Legal/Privacy counsel |
|---|---|---|---|---|---|---|---|---|
| Approve corporate security policies | A | R | C | C | I | C | C | C |
| Maintain policy register and review calendar | I | A/R | C | I | I | C | C | C |
| Maintain risk register and escalate material risk | A for acceptance | R | C | I | C | C | C | C |
| Create/change workforce access | I | C | R | C | A for business need | A for system permission | I | I |
| Notify joiner/mover/leaver events | I | I | R | A/R | R for role context | C | I | I |
| Conduct access reviews | I | C | R for evidence/removal | I | A for team access | A for system/data access | I | I |
| Assign data classification | I | C | C | C | C | A/R | I | C |
| Approve external sharing of sensitive data | I | C | C | I | C | A/R | I | C |
| Triage and coordinate security incident | I | C | R | C | I | C | A/R | C |
| Approve external incident notification | A for material business communications | C | I | C | I | C | R for facts | C/R for legal assessment |
| Accept a material residual risk | A | R for documentation | C | I | C | C | C | C |
| Approve policy exception | A for material residual risk | R | C | I | C | A for system risk | C | C when legal impact |

## Small-team caveat

At a 50-person startup, one person may fill several operational roles. If an independent approver is not available, record the conflict, use a second-level approval for high-risk access or risk acceptance, and review the decision retrospectively. A RACI chart clarifies responsibility but does not replace named ownership, competence, or adequate separation of duties.
